# 🛒 FMCG Marketplace Analysis — End-to-End Data Engineering Pipeline

An end-to-end **Data Engineering pipeline** built using **Databricks, Apache Spark, PySpark, and SQL** to integrate, transform, and analyze FMCG marketplace data from parent and child companies.

The project implements **Medallion Architecture**, supports both **full and incremental data loads**, follows **Fact & Dimension data modeling**, and prepares optimized datasets for **Business Intelligence and dashboarding**.

## 📌 Project Overview

The **FMCG Marketplace Analysis** project demonstrates a complete data engineering workflow for processing marketplace data generated by a **Parent Company** and its **Child Company**.

The primary objective is to build a scalable and reliable data pipeline that:

* Integrates data from multiple company sources
* Handles both historical and daily incremental data
* Cleans and transforms raw datasets
* Creates optimized **Fact and Dimension tables**
* Builds denormalized datasets for analytics
* Enables efficient business intelligence and dashboarding

## 🏗️ Architecture

The project follows a **Medallion Architecture** consisting of Bronze, Silver, and Gold layers.

```text
                 ┌─────────────────────────┐
                 │   Parent Company Data   │
                 │ Full + Incremental Load │
                 └────────────┬────────────┘
                              │
                              ▼
                 ┌─────────────────────────┐
                 │   Child Company Data    │
                 │ Full + Daily Landing    │
                 └────────────┬────────────┘
                              │
                              ▼
                    ┌──────────────────┐
                    │  Bronze Layer    │
                    │   Raw Data       │
                    └────────┬─────────┘
                             │
                             ▼
                    ┌──────────────────┐
                    │  Silver Layer    │
                    │ Clean & Transform │
                    └────────┬─────────┘
                             │
                    ┌────────┴────────┐
                    ▼                 ▼
             ┌──────────────┐  ┌──────────────┐
             │ Dimensions   │  │ Fact Tables  │
             │ Customers    │  │ Orders       │
             │ Products     │  │ Sales        │
             │ Pricing      │  │              │
             └──────┬───────┘  └──────┬───────┘
                    │                 │
                    └────────┬────────┘
                             ▼
                    ┌──────────────────┐
                    │   Gold Layer     │
                    │ Denormalized Data│
                    └────────┬─────────┘
                             │
                             ▼
                    ┌──────────────────┐
                    │    Dashboard     │
                    │ Business Insights│
                    └──────────────────┘
```

## 🔄 Data Pipeline Workflow

The overall pipeline follows these stages:

### 1️⃣ Ingestion

Raw CSV files are collected from the landing zones of the Parent and Child Companies.

```text
Raw CSV Files
     ↓
Landing Zone
     ↓
Bronze Layer
```

The pipeline supports both:

* Full historical datasets
* Daily incremental files

---

### 2️⃣ Transformation — Silver Layer

Raw data is cleaned and standardized using **PySpark**.

Typical transformations include:

* Data type standardization
* Null value handling
* Duplicate removal
* Data cleansing
* Column standardization
* Data validation
* Joining datasets
* Business-rule implementation

The cleaned data is then organized into appropriate dimension and fact structures.

---

### 3️⃣ Dimension Processing

The project processes the following major dimensions:

#### 👥 Customer Dimension

Contains customer-related information and supports analysis of customer behavior and geographical distribution.

#### 📦 Product Dimension

Contains product information required for product and category-level analysis.

#### 💰 Pricing Dimension

Stores gross pricing information used for sales and pricing analysis.

---

### 4️⃣ Fact Processing

Fact processing handles transactional marketplace data.

The pipeline supports:

* Full Load processing
* Incremental Load processing
* Daily updates
* Integration of Parent and Child Company orders

This ensures that the analytical warehouse remains synchronized with the latest available data.

---

### 5️⃣ Loading — Gold Layer

Processed fact and dimension tables are loaded into the **Gold Layer**.

The Gold Layer contains analytics-ready data optimized for:

* Business reporting
* SQL analysis
* Dashboarding
* KPI generation

---

### 6️⃣ Serving & Dashboarding

The final datasets are denormalized using **SQL queries** to improve dashboard performance and simplify analytical queries.

The resulting data powers the final **FMCG Marketplace Dashboard**.

## 🔁 Full Load vs Incremental Load

### Full Load

The full load processes the complete historical dataset.

```text
Historical Data
      ↓
Read Complete Dataset
      ↓
Transform
      ↓
Validate
      ↓
Load into Tables
```

### Incremental Load

The incremental pipeline processes only newly arrived or updated data.

```text
Daily Landing File
       ↓
Identify New/Updated Records
       ↓
Transform
       ↓
Validate
       ↓
Merge with Existing Data
       ↓
Updated Analytical Tables
```

This approach reduces unnecessary processing and makes the pipeline more scalable.

## ⚙️ How to Run the Project

### Prerequisites

Make sure you have:

* A **Databricks Workspace**
* Access to **Apache Spark**
* Python / PySpark
* SQL execution environment
* Appropriate storage access for the raw datasets

---

### Step 1 — Set Up Databricks

Create or open a Databricks workspace and configure the required compute resources.

---

### Step 2 — Upload Raw Data

Upload the contents of the `0_data/` directory to:

* Databricks File System (DBFS), or
* Cloud storage connected to Databricks

---

### Step 3 — Run Setup Notebooks

Execute the notebooks located in:

```text
1_codes/1_setup/
```

These notebooks configure the required:

* Catalogs
* Utilities
* Date Dimension
* Initial environment settings

---

### Step 4 — Process Dimensions

Run the dimension processing notebooks:

```text
1_codes/2_dimension_data_processing/
```

Process:

1. Customer data
2. Product data
3. Pricing data

---

### Step 5 — Process Fact Data

Execute the notebooks inside:

```text
1_codes/3_fact_data_processing/
```

Run the required:

* Full Load processing
* Incremental Load processing

---

### Step 6 — Generate Dashboard Dataset

Run the SQL queries available in:

```text
2_dashboarding/SQL_Queries/
```

These queries generate the denormalized datasets required for dashboarding.

---

### Step 7 — View Dashboard

The final dashboard is available as:

```text
2_dashboarding/fmcg_dashboard.pdf
```
